Build a mobile-first Delivery Partner (Rider) App for a laundry marketplace called "Saaf".

This app is ONLY for delivery riders.
It will be used on Android and iOS (Expo / React Native).
Do NOT build a web admin or dashboard for this app.

=====================================================
TECH STACK
=====================================================
- Expo (React Native)
- TypeScript
- Expo Router
- Dark Theme UI (match Saaf premium dark theme)
- REST APIs for backend communication
- Firebase Cloud Messaging for push notifications (later)
- No analytics, no charts

=====================================================
AUTHENTICATION & ACCESS CONTROL
=====================================================
- Login via email/password or phone OTP
- Rider account must have role = RIDER
- Rider status values:
  PENDING, APPROVED, ACTIVE, SUSPENDED

App behavior rules:
- If status = PENDING → show "Account under verification"
- If status = SUSPENDED → block access and show suspension message
- Only APPROVED/ACTIVE riders can access orders

=====================================================
CORE FEATURES (MVP)
=====================================================

1. Home / Availability Screen
--------------------------------
- Rider can toggle availability:
  AVAILABLE / OFFLINE
- Show current status clearly
- Rider should not receive orders when OFFLINE

2. Assigned Orders Screen (MOST IMPORTANT)
--------------------------------
- Show list of assigned orders only
- Each order card shows:
  - Order ID
  - Shop name
  - Customer address
  - Pickup or Delivery type
  - Distance (placeholder)
  - Status badge

Order lifecycle (strict):
ASSIGNED → PICKED_UP → DELIVERED

Rider can ONLY update status forward.

3. Order Detail Screen
--------------------------------
- Full order information:
  - Shop details
  - Customer name & address
  - Services summary (read-only)
- Buttons:
  - Call shop
  - Call customer
  - Mark Picked Up
  - Mark Delivered
- Confirmation modal before status change

4. Support / Disputes
--------------------------------
- Rider can raise a support ticket
- Dispute must include:
  - Category (predefined list)
  - Optional order link
  - Description
- Show dispute status:
  OPEN / IN_REVIEW / RESOLVED / CLOSED
- No direct chat in v1

5. Profile Screen
--------------------------------
- Rider details (read-only mostly)
- Vehicle type
- Logout

=====================================================
API CONTRACT EXPECTATIONS
=====================================================
Use REST APIs. Assume backend already exists.

Required APIs:
- POST   /auth/login
- GET    /rider/profile
- PUT    /rider/availability
- GET    /rider/orders
- PUT    /rider/orders/:id/status
- POST   /disputes
- GET    /disputes/mine

The app should NOT contain business logic.
All validations happen on backend.

=====================================================
UI / UX RULES
=====================================================
- Dark theme by default
- Large touch targets
- Minimal text
- High contrast status badges
- Clear empty states
- No unnecessary animations

=====================================================
CONSTRAINTS (VERY IMPORTANT)
=====================================================
- Do NOT show unassigned orders
- Do NOT allow rider to accept orders manually
- Do NOT allow rider to modify prices or services
- Do NOT allow rider to resolve disputes
- Do NOT implement live map tracking in v1
- Do NOT add admin features

=====================================================
DELIVERABLES
=====================================================
- Clean folder structure using Expo Router
- Screens:
  - login
  - status-blocked
  - home
  - orders
  - order/[id]
  - support
  - profile
- API service layer
- Clear TODOs where backend data replaces mock data

=====================================================
FINAL NOTE
=====================================================
This is a real delivery app, not a demo.
Prioritize correctness, safety, and simplicity over visual flair.
